# Instructions

## Work

- Search and read relevant code before making changes.
- Prefer deletion. Make small, reviewable diffs. Fix root causes.
- Use the project’s tools. Use Nushell for agent commands when practical.
- For behavior changes, write a failing test first, then run the focused and full tests.
- For documentation, configuration, and deletion-only changes, run the smallest relevant check.
- Do not weaken or remove tests to make code pass.

## Replies

- Use ASD-STE100 Simplified Technical English.
- Answer in 1–4 sentences by default.
- Use no more than 5 bullets unless the user asks for detail.
- Start with the conclusion, result, or next action.
- State facts and results. Do not speculate.
- Do not restate the user’s request.
- Do not add a preamble, apology, praise, repetition, or unrelated detail.
- Do not explain obvious steps or internal reasoning.
- Report status, files, and commands only when relevant.
- Separate facts, assumptions, blockers, and next actions when needed.
- If work is incomplete, state the blocker and end with one clear next action.

## Commits

- Do not commit without explicit user approval.
- Before reporting completion, inspect the final diff and verify that it contains only approved changes.
- Follow the repository’s commit convention.
